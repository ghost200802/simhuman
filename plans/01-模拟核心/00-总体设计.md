# 模拟核心 · 总体设计（初稿）

**目标：** 为 era03/era04 Demo 与全球最终版本提供同一套纯 TypeScript 模拟核心。
**空间单位：** 50 km × 50 km 方形区块；区块关系由图数据保存。

## 1. 核心职责

模拟核心是唯一权威状态的持有者，负责：

- 创建世界；
- 接收并验证命令；
- 将命令折算为效果、订单或进行中事项；
- 按固定顺序推进 tick；
- 生成差分、事件和查询结果；
- 序列化、加载和回放。

核心不渲染、不读取输入设备、不访问文件、不调用引擎 API。

## 2. 状态与配置

状态由可序列化记录、数组、整数 ID 和确定性 RNG 状态组成。配置只读，加载后完成 schema、ID 和交叉引用校验。

核心状态至少包含：

```text
WorldMeta / EraState / RngState
BlockState / EdgeState
PopulationGroup / BuildingState
InventoryEntry / TransferOrder / TransportPlan
PolityState / OngoingTask / ModifierInstance
```

不使用 class、闭包跨 tick 状态、对象互相引用或渲染对象。

## 3. 模块边界

```text
contract
config
world
effects
modifiers
systems
queries
serialize
rng
tick
```

系统只能写自己的领域字段。跨系统影响通过效果、订单、短缺结果、运输状态和进行中事项传递。

## 4. tick 执行

tick 入口拥有唯一阶段表。系统不得自行注册隐式顺序，不得在 tick 内识别玩家命令。命令只在 `applyCommand` 中改变世界。

每个阶段读取上游阶段的状态，写入自身字段；同一阶段内按稳定 ID 升序遍历，保证 RNG 消耗顺序和回放一致。

## 5. 性能结构

- 稳定实体 ID 映射到槽位；
- 高频数值采用列式数组或紧凑状态表；
- 低频文本、关系和配置使用 ID；
- 库存按实际存在的商品建立稀疏条目；
- 生产方法和需求模板预编译为整数索引；
- 事件和运输使用按到期时间排序的队列；
- 修改标记驱动 Modifier 与查询缓存重算；
- 热点路径不创建临时闭包和大对象。

## 6. 错误和版本

配置错误在加载阶段失败；命令错误返回结构化拒绝原因；存档记录配置版本；不对未知字段静默猜测。所有契约版本化，表现层只依赖契约。

## 7. 验证目标

- 16 区块 Demo 与大规模空内容压力测试共用代码路径；
- 可在无 Cocos 环境下运行核心测试；
- 回放结果与快照哈希稳定；
- `step(world, n)` 与重复 `step(world, 1)` 结果一致；
- 序列化后继续推进与原世界一致。
