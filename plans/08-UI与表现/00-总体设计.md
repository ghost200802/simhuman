# UI 与表现 · 总体设计（初稿）

**目标：** 为 era03/era04 Demo 和后续全球文明模拟提供独立的 UI、交互、信息呈现和 AI 生成小图标方案。
**边界：** 本文只规定表现层职责、界面结构、交互契约、信息层级和图标资产流程；不定义模拟规则，不直接修改核心状态。

## 1. UI 的基本原则

### 1.1 UI 不拥有规则

UI 只做三件事：

```text
读取 Query / ViewModel
→ 呈现状态、预测结果和事件
→ 把玩家意图翻译成 Command
```

UI 不计算生产、消费、库存、人口、运输、战争或治理结果，不直接改写模拟核心状态。

### 1.2 信息按决策组织

每个界面首先回答：

- 当前发生了什么；
- 为什么发生；
- 玩家现在能做什么；
- 操作会消耗什么；
- 可能带来什么后果。

不以系统内部对象数量作为 UI 分栏依据。

### 1.3 早期与后期使用同一界面骨架

远古阶段没有价格、货币和贸易时，对应面板显示生产、消费、储存、缺口和运输；后续解锁市场后，在同一面板追加持续运输、价格和贸易信息，不切换成完全不同的 UI 系统。

## 2. 表现层分层

```text
UI Shell
├─ 世界地图层
├─ 区块信息层
├─ 顶部资源与时间栏
├─ 命令面板层
├─ 事件与警报层
├─ 图鉴与知识层
└─ 帮助与解释层
```

表现层内部可使用 Cocos 节点、组件和动画，但只能通过核心契约访问模拟状态。

## 3. Demo 主界面

era03/era04 Demo 采用一个主地图界面，不把核心体验拆成多个互相独立的场景。

### 3.1 主地图

地图显示：

- 16 个方形区块；
- 区块地形和已知资源；
- 玩家控制范围；
- 外部社群；
- 道路、河流、山口和运输边；
- 当前运输中的路线；
- 可裂变候选区块；
- 短缺、断粮、失控和战争等状态标记。

地图坐标只负责显示方形区块，不由 UI 推导邻接关系；邻接、路径和通行状态来自核心查询结果。

### 3.2 顶部状态栏

顶部只显示玩家当前必须持续关注的全局读数：

- 当前时代与日期；
- 总人口；
- 食物可用量与预计支撑期；
- 当前生产与消费差额；
- 储存容量与占用；
- 运输中物资；
- 待处理警报；
- 暂停、单步、快进和速度。

商品尚未进入价格体系时，不显示虚假的价格和货币栏。

### 3.3 区块侧栏

点击区块后显示：

- 区块名称和地形；
- 人口与劳动力；
- 生产设施及当前产出；
- 本期消费与缺口；
- 储存容量、库存与损耗；
- 运输到达和离开；
- 凝聚、控制和治理状态；
- 可用命令及其前置条件。

### 3.4 命令面板

命令面板只显示当前已解锁且满足条件的命令：

- 调整生产；
- 建造储存设施；
- 发起手动调配；
- 建立持续运输；
- 发起聚落裂变；
- 选择治理方式；
- 战争相关命令。

未解锁机制不显示完整按钮，必要时显示知识或时代提示。

## 4. 信息展示层级

### 4.1 第一层：结果摘要

玩家首先看到结果：

```text
粮食短缺：预计 2 个月后出现
来源：本区块产出不足，储存已耗尽
可执行：建设仓库、调整生产、手动调配
```

### 4.2 第二层：因果拆解

点击摘要后显示：

```text
生产 80
- 人口消费 100
- 建筑维护 5
+ 运输到货 10
= 库存变化 -15
```

### 4.3 第三层：原始明细

需要时再显示人口群体、建筑、库存条目、运输订单和 Modifier 等底层数据。底层字段不是默认首页内容。

## 5. 关键面板

### 5.1 生产与消费面板

显示：

- 本期产出；
- 本期消费；
- 储存变化；
- 商品缺口；
- 生产方法与工具条件；
- 预计下期结果。

没有价格的阶段只显示数量、满足率、缺口和损耗，不显示货币价值。

### 5.2 运输面板

显示：

- 手动调配订单；
- 持续运输计划；
- 运输中的库存；
- 路线容量；
- 预计到达时间；
- 路线中断原因；
- 到货损耗。

自动贸易、价格和市场订单只有解锁后才出现。

### 5.3 聚落裂变面板

显示：

- 候选目标区块；
- 需要投入的人口与物资；
- 建立进度；
- 新区块的预计生产和消费；
- 运输距离与治理压力；
- 取消或失败后果。

### 5.4 时间与事件面板

显示：

- 当前 tick 和日期；
- 正在推进的事项；
- 事件结果；
- 事件对库存、人口、生产和治理的影响；
- 可追溯的原因链。

## 6. 交互契约

UI 不调用核心内部函数，不直接写状态，只构造版本化命令：

```ts
interface UiCommandRequest {
  commandType: string;
  payload: Record<string, number | string | boolean>;
  sourceViewId: string;
}
```

表现层将用户输入转换为核心认可的 `Command`；核心返回：

- 成功后的 diff；
- 结构化拒绝原因；
- 事件；
- 查询刷新标记。

UI 不自行判断命令成功与否，只展示核心返回结果。

## 7. 视觉设计方向

### 7.1 总体气质

- 2D 俯视地图；
- 清晰的区块边界；
- 低噪声背景；
- 图标优先于大段文字；
- 重要状态使用颜色、形状和动画共同表达；
- 远古阶段使用自然材料、火、石、木、陶等视觉语汇；
- 后期图标通过材质和结构变化扩展，不更换整套 UI 语言。

### 7.2 状态颜色

颜色不能作为唯一信息来源。每个状态同时拥有颜色、图形和文字标签：

| 状态 | 默认语义 | 辅助表现 |
| --- | --- | --- |
| 正常 | 绿色或青色 | 稳定图形 |
| 注意 | 黄色或橙色 | 三角或脉冲 |
| 短缺 | 红色 | 缺口符号与闪烁 |
| 运输中 | 蓝色 | 方向箭头与路径动画 |
| 未知 | 灰色 | 问号或遮罩 |
| 已解锁 | 高亮色 | 点亮边框 |

### 7.3 地图表现

区块边界、所有权、地形、资源、运输和警报使用独立图层。图层可以开关，避免地图同时显示所有信息。

## 8. AI 生成小图标方案

### 8.1 使用范围

AI 生成只用于小尺寸 UI 图标、资源图标、状态徽记、建筑缩略图和时代视觉变体。核心 UI 结构、字体、布局、颜色规范和交互图形不依赖生成结果。

### 8.2 图标约束

每个图标必须：

- 单一主体；
- 轮廓清晰；
- 适合 16、24、32、48 px 等尺寸；
- 透明背景；
- 避免文字、数字、复杂透视和细碎纹理；
- 使用固定光照方向；
- 使用统一描边与阴影规则；
- 通过后处理统一尺寸、边距和色彩。

### 8.3 生成流程

```text
图标语义表
→ 统一风格提示词
→ 生成候选图
→ 人工筛选
→ 去背景与裁切
→ 尺寸与颜色标准化
→ 小尺寸可读性检查
→ 资产命名与版本登记
→ UI 集成测试
```

### 8.4 资产命名

```text
icon_{category}_{id}_{variant}_{version}.png
```

例如：

```text
icon_commodity_food_grain_v01.png
icon_status_shortage_v01.png
icon_building_storage_01_v01.png
```

### 8.5 生成提示词模板

```text
SimHuman UI icon, [主体], [时代/材质], centered single object,
clear silhouette, flat 2D game icon, consistent outline,
soft controlled shadow, limited palette, transparent background,
no text, no letters, no numbers, no watermark, readable at 24 px
```

每个图标的语义、禁用元素、主色、时代变体和验收尺寸必须记录在独立资产清单中；本方案不直接规定具体图标内容。

## 9. 性能与资源策略

- 图标按图集打包；
- 同一语义的尺寸使用统一裁切规则；
- 地图状态图标使用批处理或合并渲染；
- UI 查询结果采用缓存和脏标记；
- 大量区块信息不创建一份永久 UI 节点；
- 只为当前可见区块创建高频表现对象；
- 规则计算仍全部在核心，表现层只做渲染。

## 10. Demo 验证范围

首个 Demo 只需要：

- 16 区块地图；
- 顶部状态栏；
- 区块侧栏；
- 生产与消费面板；
- 库存与储存面板；
- 手动调配面板；
- 聚落裂变面板；
- 事件和原因链提示；
- 一组 AI 生成资源、建筑和状态图标。

市场价格、自动贸易、复杂国家面板和后期时代图标先保留接口与视觉规范，不在首个 Demo 中伪造内容。

## 11. 验收标准

- UI 不直接修改核心状态；
- 所有按钮都能映射到版本化命令或查询；
- 无价格阶段不显示虚假价格；
- 玩家能从警报追溯到生产、消费、库存或运输原因；
- 16 区块地图在不同缩放下保持可读；
- 图标在 16–48 px 范围内可识别；
- AI 生成图标经过统一后处理后，风格、边距和尺寸一致；
- 切换地图图层不会改变模拟结果。
