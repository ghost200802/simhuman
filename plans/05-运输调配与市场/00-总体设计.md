# 运输调配与市场 · 总体设计（初稿）

**目标：** 在同一套区块图和全球实时 tick 上，逐步实现手动调配、持续运输、贸易和价格，不把未解锁的市场机制提前带入远古阶段。

## 1. 演进顺序

```text
生产与消费
→ 储存
→ 手动调配
→ 市场与持续运输
→ 贸易与价格
```

所有区块和国家始终运行生产、消费和库存；市场能力是可解锁的运输与计价机制，不是另一套世界模拟。

## 2. 手动调配

玩家指定来源区块、目标区块、商品和数量，系统沿图寻找路径并结算时间、容量和损耗。订单是一次性记录，不自动寻找新目标。

## 3. 持续运输

市场能力出现后，玩家可以建立固定来源、目标、商品、周期、数量和优先级的运输计划。计划不读取价格，不自动换路或换目标；线路中断时记录未完成状态。

## 4. 贸易与价格

贸易能力出现后，市场根据供给、需求、库存、货币和运输成本生成买卖与运输。价格只在满足配置条件的商品和区块中启用。贸易、持续运输和手动调配同时存在。

## 5. 运输状态

运输中的商品是独立的可序列化记录，保存来源、目标、商品、数量、出发 tick、到达 tick、损耗、路线版本和中断状态。商品到达前不计入目标可用库存。

## 6. 性能结构

- 图路径按版本缓存；
- 运输按到期时间队列推进；
- 订单只保存非零数量和有效引用；
- 手动订单、持续计划和贸易订单使用同一运输状态格式；
- 市场匹配算法独立于表现层；
- Demo 只启用手动调配，后续能力沿同一接口增加。

## 7. Demo 验证

使用 16 个区块验证来源库存冻结、路线容量、运输时间、损耗、到货和中断恢复。市场价格和自动贸易先保留契约位置，不在 era03/04 首个切片中伪造。
