# SimHuman · era03/era04 Demo 总体实现方案（初稿）

**状态：** 待确认的总体方案，不直接作为程序接口定稿。
**目标：** 用少量数据验证 era03 的农业增长与脆弱、era04 的聚落裂变与凝聚，同时从第一天起采用可扩展到全球实时模拟的架构。
**空间单位：** 全局只有一种空间单位：固定 50 km × 50 km 方形区块。区块之间的连接由图数据表达。

## 1. 目标与非目标

### 1.1 Demo 必须验证

- 生产、消费、储存和损耗形成闭环；
- 食物、工具和种子短缺会产生可解释后果；
- 没有贸易时可手动跨区块调配物资；
- 市场与持续运输可以作为后续能力接入，但不提前伪造价格；
- 人口增长会提高产出，也会提高消费、土地和治理压力；
- 聚落裂变会带来新生产能力，同时消耗人口、物资和治理能力；
- 相同种子与命令序列得到相同结果；
- 16 个区块的数据结构与全球地图的区块数据结构相同，只减少内容数量。

### 1.2 Demo 暂不验证

- 完整货币、价格、自动贸易和金融；
- 全球完整商品目录；
- 全部时代的技术树；
- 复杂外交、法律和宗教系统；
- 大规模战争的全部战术内容。

这些内容不应通过临时分支塞入 Demo；接口要为最终系统保留稳定入口，内容可以暂时为空。

## 2. 最终目标约束

### 2.1 全世界同一模拟规则

所有已生成区块、政权、人口群体、建筑、库存和运输都属于同一权威世界状态，并按同一 tick 顺序推进。Demo 的“小”只体现在配置条目和区块数量少，不体现在另写一套轻量模拟。

### 2.2 数据与逻辑分离

- 数值、商品、生产方法、需求、建筑、地形、边类型和效果均走配置；
- 核心状态只保存 ID、整数数值、数组和可序列化记录；
- 新内容优先新增配置，不新增规则分支；
- 模拟核心不依赖 Cocos 或任何平台 API。

### 2.3 性能方向

- 热点状态使用列式数组或紧凑记录，避免每 tick 创建临时对象；
- 商品库存使用稀疏条目，不为每个区块预分配完整商品矩阵；
- 人口以人口群体为单位，不逐人建实体；
- 图使用稳定 ID 和压缩邻接表；
- 生产方法、需求规则和效果在加载时索引化；
- tick 内使用固定阶段和批量遍历；
- `// PERF` 标注需要基准测试的路径。

## 3. 总体分层

```text
配置与契约层
    ↓
模拟核心层
    ├─ 世界状态与区块图
    ├─ 人口与社会
    ├─ 生产、消费与库存
    ├─ 运输、手动调配与市场
    ├─ 聚落裂变与治理
    └─ 战争与占领
    ↓
查询、差分与事件输出
    ↓
Cocos 表现层
```

表现层只渲染查询结果、显示事件并派发命令；核心层不接收节点、回调或 UI 对象。

## 4. 核心状态

Demo 和最终版本使用同一类状态：

```text
World
├─ worldTime
├─ seed / rngState
├─ eraState
├─ blockStates[]
├─ edgeStates[]
├─ populationGroups[]
├─ buildingStates[]
├─ inventories[]
├─ transferOrders[]
├─ transportPlans[]
├─ polityStates[]
├─ ongoingTasks[]
└─ eventQueue[]
```

所有跨实体关系只保存整数 ID。实体销毁和槽位复用必须使用代号或世代号防止悬空引用。

## 5. tick 总顺序

Demo 采用固定月度 tick；UI 可以快进，但不能改变规则时间单位。

```text
1. 读取本 tick 的时间和时代状态
2. 聚合失效缓存与 Modifier
3. 运输推进与已到货物入库
4. 生产
5. 人口、建筑和军队消费与维护
6. 储存、损耗与短缺结果
7. 人口变化与迁移
8. 聚落裂变与治理事项推进
9. 战争、占领与控制度推进
10. 压力、事件和随机结果
11. 生成 diff / event / query cache
```

顺序是规则的一部分；系统不互相直接调用，不在 tick 中判断“玩家命令”。命令在入口折算为效果、订单或进行中事项。

## 6. Demo 场景

### 6.1 地图

- 4×4 方形区块，共 16 个；
- 使用稳定区块 ID 和图边；
- 默认四边连接，额外放置河流、道路、山口和季节性边；
- 只生成少量地形、气候、资源和外部社群配置；
- 地图显示使用方形地块，但核心只读取图结构。

### 6.2 内容规模

- 3–6 个商品；
- 3–8 个生产方法；
- 3–6 类需求模板；
- 10–30 个建筑实例；
- 10–40 个人口群体；
- 1 个玩家政权、1–3 个外部政权或社群；
- 1 个可裂变主聚落与 1–3 个候选区块。

内容少是测试数据，不改变数组、索引、订单和存档的最终形态。

## 7. 玩家命令边界

Demo 只开放能表达核心张力的命令：

- 调整生产活动；
- 建造或升级储存设施；
- 发起一次性手动调配；
- 建立或取消持续运输（若该能力已解锁）；
- 迁移人口；
- 发起聚落裂变；
- 选择新聚落区块与投入物资；
- 设置治理方式；
- 战争相关命令仅接入既有战争契约。

玩家不逐个决定人口消费、单件库存归属、运输队逐步移动或随机事件结果。

## 8. 运行、存档与测试

### 8.1 核心入口

```text
initWorld(seed, config)
applyCommand(world, command)
step(world, count)
query(world, query)
serialize(world)
load(snapshot)
```

### 8.2 必须具备的测试

- 同种子确定性回放；
- 生产—消费—库存守恒；
- 运输到货和损耗守恒；
- 裂变投入与新聚落初始状态一致；
- 区块图路径稳定；
- 存档序列化往返一致；
- 16 区块、256 区块、目标全球区块规模的性能基准入口。

## 9. 交付顺序

1. 契约、配置加载、世界状态和确定性 tick 骨架；
2. 16 区块图与查询；
3. 生产、消费、储存和短缺；
4. 手动调配与运输；
5. 人口增长和压力；
6. 聚落裂变与治理；
7. 既有战争系统接入；
8. 统一命令日志、回放、存档和性能基准；
9. 再进入市场价格、自动贸易和更大内容量。
