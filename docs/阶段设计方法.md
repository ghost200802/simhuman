# SimHuman 阶段设计方法

**适用：** 为任意阶段产出游玩核心与后续设计文档时。
**边界：** 只写规则。不含任何具体阶段的设计内容。

**一句话：** 先定"这个时代玩家在玩什么"，再定机制；机制里凡挂不到核心张力上的，都不进这个时代。

---

## 一、产出物与顺序

每个阶段一个目录：

```
docs/阶段文档/NN-阶段名/
    00-提纲.md
    01-游玩核心.md
    02-阶段详案.md
    03-依据与推导.md
    （按需增加）
```

另有两份跨阶段的顶层文档：

- **汇总文档** `docs/时代主线与转换条件.md`——每个时代的六句话与进入下一时代的转换条件。
- **术语表** `docs/术语表/`——全项目关键名词的权威定义，**按概念族分成多份**。**任何文档要用一个表里没有的名词，先把它加进表，再在文档里用。**

阶段设计的总顺序：

```
提纲 → 游玩核心 → 阶段详案 → 屏幕清单与跳转图 → 契约包 → 实现
```

「依据与推导」不在这条顺序上，它随「游玩核心」并行推进。汇总文档随各阶段定稿逐段补齐。

规则：

1. 不得跳过游玩核心直接写阶段详案。
2. 不得在游玩核心定稿前开始界面设计。
3. 一个阶段一个目录，文档之间不建立包含或同步关系，各自独立可读。
4. 新增文档先建目录，不平铺在 `docs/阶段文档/` 根下。
5. **结论与依据分开存放。** 提纲、游玩核心、以及汇总文档里该时代的核心点，**只写结论**；文献依据、推导过程、设计取值标注、以及查不到与有争议的部分，一律写入该阶段的「依据与推导」。
6. **汇总文档里每个时代只回答六句话 + 一张转换条件表，不出现别的内容。** 更详细的写在各自的阶段文档中。

## 二、每个时代必须回答的六个问题

每个时代的游玩核心，以及汇总文档里该时代的核心点，**必须按下列六项逐条回答**。

**不得缺项，不得合并，不得改写项目名称。** 尚未确定的，显式写"待定"，不得省略该项。

六项在文档里一律用**短名**。短名与问题的对应关系固定如下，不得改写：

| # | 短名 | 问题 |
| --- | --- | --- |
| 1 | **第一次出现什么** | 这个时代在历史上第一次出现了什么 |
| 2 | **独有体验** | 玩家会经历什么别处没有的感受 |
| 3 | **核心张力** | 玩家反复权衡的那一对矛盾是什么 |
| 4 | **核心循环与乐趣** | 核心循环长什么样，乐趣产生在哪一环 |
| 5 | **不该有的** | 这个时代不该让玩家做什么 |
| 6 | **比上一条陡在哪** | 新增的这条成长线，比上一条陡在哪里 |

### 游玩核心的固定章节顺序

```
一句话
1. 时代的叠加原则
2. 第一次出现的东西：<问题 1 的答案>
3. 独有体验
4. 核心张力
5. 核心循环
6. 核心机制清单
7. 这个时代不该有的
8. 与相邻时代的成长线对比
9. 验收要点
```

- 六问已分布在 2–5、7、8 各节，不另起一节重复回答。
- **验收要点只写在「游玩核心」第 9 节**，不在其他文档重复。
- 章节顺序不得调整，不得增删。

### 依据与推导的固定尾节

正文分节自由（按主题分、或按六问分都可以），但**尾部三节必须有，顺序不得调整**：

```
查不到、有争议、未定的部分
设计取值标注
来源
```

- 「查不到、有争议、未定」如实记录否定的结果，查不到就说查不到，不编造。
- 「设计取值标注」逐条列出哪些是设计决定、不是文献结论，与文献数字显式分开。

### 通用前提：时代推进是叠加，不是替换

先确立这一条，它决定六个问题的表述方式。

```
本时代 = 已有能力的全集 + 一条新增的成长线
```

1. 新增的那条线**更陡、上限更高**；旧的那些线**一直可用，上限不变**。
2. 玩家行为的变化来自"新线更划算"，不是"旧能力被拿走"。
3. 描述时代差异时只写**新增了什么、上限提高了多少**，不写"从 A 变成了 B"。
4. **倒退通过失传发生，不通过时代回退。** 时代标签不退；崩溃表现为人口崩塌、储存丢失、部分技能失传，玩家仍在本时代。
5. 因此任何"禁止玩家继续使用旧手段"的规则都是错的。正确做法是**让旧手段的代价随积累上升**。

### 问题 1：这个时代在历史上第一次出现了什么

- 不写"发生了什么"，写**哪个变量第一次变得重要**。
- 答不出来，说明这个时代的定位有问题，先修定位。

### 问题 2：玩家会经历什么别处没有的感受

- 必须是**由本时代新增的那条成长线直接产生的**，答题时要能说清"在这之前不会有人这样感觉"。
- **不要求后续时代失去它**——叠加原则下能力一直可用；但后续时代不得以它为主要体验。
- 答不出来，说明这个时代没有存在理由，应考虑并入相邻时代。

### 问题 3：玩家反复权衡的那一对矛盾是什么

- 必须是**一对**，用一句话表述，不是一串并列。
- 这一对就是核心张力。后续一切机制都必须挂到它的两侧之一。
- 表述里要能看出两侧的**代价**分别是什么，只有收益没有代价的不算张力。

### 问题 4：核心循环长什么样，乐趣产生在哪一环

- 画出循环，标出**正反馈在哪、刹车在哪**。
- 逐个列出乐趣点，每个都要说明它为什么产生乐趣。
- 慢变量必须有**中间可见态**。不允许只靠一次大跳变提供反馈。

### 问题 5：这个时代不该让玩家做什么

分三层写，不得只写中间一层：

1. **系统上不存在的东西**——这个时代根本没有这个系统。
2. **属于后续时代的**——这个时代有，但要留给后面的时代。
3. **针对本时代的禁令**——本时代的系统不变量（例："不得让图鉴掉"）。破了它，本时代的张力就没了。

- 缺这一条，本时代会把后面时代的乐趣提前吃掉，两个时代变成同一件事。

### 问题 6：新增的这条成长线，比上一条陡在哪里

- 用三段式各写一行：上一时代 / 本时代 / 下一时代，每行写**新增的成长线**与**上限提高到了哪里**。
- 不得写成能力替换式的描述。
- 写不出"上限提高了多少"，说明这条线不够陡，这个时代没有存在理由。
- 写不出与相邻时代的分界，说明阶段划分本身有问题，应先修划分，不要硬写。

### 补充：失败态的定义

必须写明崩溃或失败在本时代意味着什么：**损失什么、保留什么、恢复到什么起点**。

**只写在「提纲」的"进入与倒退"一节**，不在其他文档重复。

不写这一条，玩家要么卡死，要么感受不到代价。

## 三、时代转换规则

适用于所有时代。

1. 转换必须由玩家手动确认，不得自动发生。
2. 条件不满足时不可进入。条件满足后转换入口点亮。
3. 确认框必须给出对比：第一次出现什么、获得什么、失去什么、保留什么。
4. 取消后玩家继续留在当前时代。条件满足后本时代必须仍有可玩内容。
5. 条件是状态量，不是清单。
6. 时代标签从不回退。转换是单向的。
7. 每条条件都必须在本时代有机制承载。
8. 条件之间是合取，全部满足才可进入。
9. 条件必须是玩家能达成的状态。
10. 不得把依赖地图或邻居的偶然因素做成条件。
11. 条件写成一张两列表：列为「**组**」与「**条件**」。**组**标明这条条件由哪类系统承载，取值固定为 **知识 / 状态 / 设施 / 科技**。表下一律写一句"全部满足后由玩家手动确认进入"。

## 四、每个点怎么确定

**总则：每个时代动笔之前，先调研相关文献。** 所有设计结论都必须以历史知识为依据，不得凭设想直接给出。文献给不出方向的地方，按 4.3 走设计取舍并如实标注。

每个待定的点，只能通过以下三种方式之一确定。**必须标明用的是哪一种。**

### 4.1 历史事实有争议或不确定 → 先查文献

1. 不得凭印象写历史结论。涉及年代、机制、比例、因果的，一律先查证。
2. 查证后**如实报告否定的结果**。查不到就说查不到，不编造。
3. 文献给出的**方向**用于确定设计方向；文献给出的**数字**只有可溯源时才能引用。

### 4.2 文献给方向，设计给数值 → 分离标注

1. 结构性结论可以直接采用为设计方向。
2. 设计数值必须显式标注"这是设计取值"，并说明它落在文献的哪个区间内。
3. 来自**单一来源、单次回归或单一病理/社会系统**的比例，必须保留适用范围说明，不得当成普适常数。
4. 文献不给某个数值时，不得编造一个"文献上限""文献比例"。

### 4.3 设计取舍 → 给推导，请确认

1. 每个取舍点只给**一个**推荐方案加理由，不罗列一堆选项让人挑。
2. 明确区分三类内容：**用户已提出的需求 / 当前方案 / 仍可调整的推导**。
3. 用户修正时**全盘吸收**，不保留原方案，不回护，不在后续论证中把被否掉的方案重新捡回来。
4. 一次只推进一个点，确认后再往下。

### 4.4 修改已定结论

1. **改动任何已定结论前，先展示原文与拟改方案，获得确认后再动。** 不先斩后奏。
2. **不得擅自删除。** 用户说"不加条件"不等于"删掉条件"；含义不明时先问，不自行解释。
3. 一处结论改动后，主动排查它在其他文档里的连带引用，**一并列出待确认**，不单方面改。
4. 删除任何内容前先看它是什么：找不到替代、或不是自己写的，先报告，不直接删。

### 4.5 目标不清晰时

- 目标清晰时直接推进最短可行路径。
- 目标不清晰时**先列出缺失的决策点**，不自行假设，不"先做着看"。
- 已经确定过的结论不重复讨论，除非出现新信息。

## 五、防止"堆数值"的闸门

每一条都必须能在文档里被检验。

1. **每个机制必须能映射到核心张力的某一侧。** 映射不上的，不进这个时代。
2. **机制之间必须互相咬合。** 每个新机制至少要指出它与另外两个已有机制的接口在哪里。
3. **时代主线计量必须接进风险轴。** 只涨不跌的进度条不构成主线计量，它只是数字在变大。**科技节点与图鉴不在此列**——前者会流失，后者按设计就是永久解锁。
4. **每个时代必须留下至少一个解不掉的压力。** 所有问题都能被解决的机制会让时代失去张力。
5. **新增任何一项计量、属性或系统前，先回答：删掉它，核心体验会损失什么。** 答不出来就不加。
6. **不引入玩家无法验证的属性。** 玩家看不见、也无法通过结果感知的属性，等于不存在。
7. **进入下一时代的每一个门槛条件，本时代都必须有机制承载。** 不能要求玩家做到本时代不存在的事。
8. **条件满足后，本时代必须仍有可玩内容。** 否则转换确认框上的"取消"是个假选项。

## 六、进一步怎么实现

游玩核心定稿后，按下述顺序推进。

### 6.1 阶段详案

展开为可实现规格，至少包含：

| 项 | 内容 |
| --- | --- |
| 关键计量 | 名称、范围、受什么影响、玩家能否看到 |
| 决策清单 | 时机、可选范围、立即效果、长期效果、**折成哪条命令** |
| 信息清单 | 玩家必须看到什么、变化频率、聚合程度 |
| 资源与生产 | 本时代出现的资源、设施、产物、转换关系 |
| 发展节点 | 三类——**科技 / 图鉴 / 社会**——的节点清单，外加**文明 flag**（如"稳定火源"）。区分完整范围与首个切片范围 |
| 事件 | 主题、触发条件、后果类型 |
| 时代转换 | 本时代进入下一时代的条件、以及这些条件在本时代的承载机制 |

硬性要求：

1. 详案中的每一条，必须能指回游玩核心的某一条张力。指不回的删掉。
2. **决策清单是双出口的**：一份喂屏幕清单，一份喂内核契约——每条决策对应一条命令定义。
3. 必须单独列出**首个切片范围**，并保证该范围覆盖核心张力。内容量不进首版验收。

### 6.2 屏幕清单与跳转图

- 屏幕是**承载决策与信息的容器**，由决策清单和信息清单推导，不得凭空新增。
- 一个屏幕可以承载多条决策与信息；一条决策也可以跨多个屏幕。
- 屏幕清单定稿后再定导航关系与层级。

### 6.3 契约包

数据映射、命令清单、槽位。做法另见界面制作规范。

### 6.4 实现

按界面制作规范执行。

**反查规则：** 详案里出现、但游玩核心里没有对应张力的机制，删掉；界面上出现、但决策清单里没有对应决策的交互，删掉。

## 七、文档纪律

1. 一个阶段一个目录，一份文档只讲一件事。
2. **规则、结论、依据三者分开存放。** 规则文档只写要求与禁止，不写任何具体阶段的内容；结论文档只写结论，不写判定标准，也不写依据；依据文档只写依据，不重复结论。
3. 每份文档独立可读：不引用其他文档的编号或段落，不建立同步关系。
4. **每个关键信息只写入一个权威源**，其他文档最多放链接或一句状态摘要。已定：失败态只在「提纲」，验收要点只在「游玩核心」，转换条件只在汇总文档。
5. **不得描述其他文档的完成状态。** 「待建」「待调研」「某某落定后补」「本阶段不设计」这类话，**只能写在该系统自己的文档里**。一个文档只说自己做到哪一步，**不说别人做到哪一步**。
6. 一次只改当前任务涉及的文档。
7. 文档只记录**当前结论与依据**，不记录执行过程、失败尝试和对话历史。
8. 保留历史用版本控制，不用复制文件。
9. **同一概念全文只有一个名字**，一律以 `docs/术语表/` 为准。表里没有的名词，先加进表再用。
10. **不用 P / s / L 这类代码符号**，一律用中文表述（进度、研发、流失）。

## 八、完成检查表

一个阶段定稿前，逐条确认：

- [ ] 六问一律用**短名**，未确定的显式写"待定"，没有缺项或合并
- [ ] 六个问题全部有答案，且各自独立成立
- [ ] 独有体验由**本时代新增的成长线直接产生**，没有写成"后续时代不具备的能力"
- [ ] 游玩核心九节齐全，顺序未被调整
- [ ] 核心张力写成了**一对**，两侧都有明确代价
- [ ] 核心循环画出来了，正反馈与刹车都标了
- [ ] 每个乐趣点都说明了"为什么产生乐趣"
- [ ] 慢变量有中间可见态
- [ ] 失败态写明了损失什么、保留什么
- [ ] 本时代不该有的能力写满**三层**（系统上不存在的 / 后续时代的 / 本时代的禁令）
- [ ] 三段式质差都写得出来
- [ ] 每个机制都能映射到核心张力
- [ ] 每个机制至少指出与另外两个机制的接口
- [ ] 至少留下一个解不掉的压力
- [ ] 涉及历史事实的结论都已查证，查不到的已标注
- [ ] 设计数值已标注"设计取值"，与文献数字分离
- [ ] 单一来源的比例已标注适用范围
- [ ] 新增的每一项计量或属性都回答过"删掉会损失什么"
- [ ] 全文没有"能力被替换"式表述，时代差异一律写成"新增了什么、上限提到哪"
- [ ] 没有禁止玩家继续使用旧时代手段的规则；旧手段的代价随积累上升
- [ ] 倒退写成"失传"，没有写成"时代标签回退"
- [ ] 进入下一时代的每个门槛条件，本时代都有机制承载
- [ ] 条件满足后本时代仍有可玩内容
- [ ] 转换条件写成了带「组」的两列表（知识 / 状态 / 设施 / 科技）
- [ ] 依据文档尾部三节齐全：查不到与有争议 / 设计取值标注 / 来源
- [ ] 失败态只在提纲、验收要点只在游玩核心、转换条件只在汇总文档，没有重复
- [ ] 汇总文档里本时代只有**六句话 + 一张转换条件表**，没有别的内容
