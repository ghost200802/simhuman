# 市场系统 · 游戏设计

**定位：** 定义生产物如何在区块内消费、储存、调配、持续运输与贸易。
**边界：** 本文只写游戏规则、玩家操作、状态与结算；历史依据另存于《市场系统 · 依据与推导》。
**空间单位：** 全局只有一种空间单位：固定 50 km × 50 km 的方形区块。库存、生产、消费、运输和价格均直接挂在区块上。

**一句话：** **先有生产与消费，再有储存；先有玩家调配，再有持续运输；最后才由贸易产生价格并自动寻找运输。**

## 1. 系统管什么

市场系统管生产物离开生产环节之后的流向：

- 区块内消费；
- 储存与损耗；
- 区块之间的一次性手动调配；
- 市场建立后的持续运输；
- 贸易建立后的价格与自动运输；
- 国家用钱购买商品，以及商品贸易产生的税收与流动资金。

市场系统不管：

- 资源、建筑和生产方法如何产生实际产出；
- 人口如何增长、死亡、迁移或改变职业；
- 军队如何战斗；
- 商品对应的技术如何研发。

生产系统给出产出，市场系统处理产出之后的消费、库存与流通。

## 2. 经济机制的解锁顺序

```text
生产与消费
→ 储存
→ 手动调配
→ 市场与持续运输
→ 贸易与价格
```

前一阶段的机制在后一阶段保留，不因新机制出现而删除。

### 2.1 生产与消费

最早期区块只计算：

```text
本期生产
→ 本期消费
→ 剩余部分按保存能力处理
```

此时没有价格、货币、贸易和自动运输。

### 2.2 储存

储存需要同时具备：

- 已掌握的储存技术；
- 已建成且正常运行的储存设施。

没有储存技术或设施时，生产超过本期消费的部分按商品保存规则损耗，不进入可用长期库存。

玩家不逐笔决定“储存还是消费”。消费由人口、建筑和军队的需求规则自动执行；剩余部分由储存能力自动接收，超过容量的部分自动损耗。

### 2.3 手动调配

没有贸易机制时，玩家可以把一个区块的库存调配到另一个区块。

玩家命令包括：

- 来源区块；
- 目标区块；
- 商品；
- 数量。

系统根据图上的连接边计算路径、运输时间、容量和损耗。

手动调配是一次性命令，不会自动重复，也不会根据价格寻找其他目标。

### 2.4 市场与持续运输

市场机制出现后，玩家可以建立持续运输计划，但此时仍可以没有价格和货币。

持续运输计划包括：

- 来源区块；
- 目标区块；
- 商品；
- 每期数量；
- 运输周期；
- 优先级。

持续运输由玩家建立并维持。它不会自动寻找新的来源或目标，也不会根据价格改变方向。

### 2.5 贸易与价格

贸易机制出现后，新增：

- 货币计价；
- 商品价格；
- 买方与卖方；
- 贸易订单；
- 根据供需和运输成本自动形成的运输；
- 贸易利润与价格反馈。

贸易运输不取消手动调配和持续运输，三者同时存在：

| 运输方式 | 建立方式 | 是否自动寻找对象 | 是否需要价格 |
| --- | --- | --- | --- |
| 手动调配 | 玩家一次性命令 | 否 | 否 |
| 持续运输 | 玩家建立计划 | 否 | 否 |
| 贸易运输 | 市场自动匹配 | 是 | 是 |

## 3. 区块状态

每个区块需要保存：

| 状态 | 说明 |
| --- | --- |
| **生产产出** | 本期由生产系统交给市场系统的商品数量 |
| **可用库存** | 当前可被消费、调配或出售的商品 |
| **储存容量** | 由储存技术、设施等级和运行状态共同决定 |
| **储存损耗** | 商品保存过程中按配置产生的损失 |
| **消费需求** | 人口、建筑、军队和其他系统提交的本期需求 |
| **手动调配订单** | 玩家发起的一次性运输 |
| **持续运输计划** | 玩家建立的周期性运输 |
| **贸易订单** | 市场自动生成的买单和卖单 |
| **价格** | 贸易机制解锁后才启用的商品计价 |
| **运输中库存** | 已离开来源区块、尚未到达目标区块的商品 |

## 4. 消费结算

消费由需求方自动执行，玩家不直接分配单个居民的商品。

结算顺序为：

```text
上期库存
+ 本期生产到货
+ 已完成运输
→ 人口、建筑和军队消费
→ 剩余部分进入储存
→ 超出储存能力的部分损耗
```

当可用商品少于需求时，市场系统只记录实际满足量与缺口；健康、生产效率、士气、人口变化等后果由对应系统读取缺口结果。

## 5. 储存结算

储存能力由配置计算：

```text
有效储存容量
= 技术提供的容量
× 设施等级
× 设施运行效率
```

不同商品可以拥有不同的：

- 最大保存期；
- 保存损耗率；
- 储存容量占用；
- 保存设施要求；
- 最低安全储备要求。

储存设施内部的商品接收顺序由配置决定，不提供逐件手动摆放操作。

## 6. 手动调配

```ts
interface ManualTransferOrder {
  id: number;
  fromBlockId: number;
  toBlockId: number;
  commodityId: number;
  amount: number;
  issuedAt: number;
  routePolicyId: number;
}
```

订单创建后：

1. 从来源区块冻结可调配库存；
2. 根据区块图寻找可用路径；
3. 按路径容量拆分或延迟运输；
4. 按运输时间推进；
5. 到达后写入目标区块库存；
6. 路线中断时按配置处理滞留、退回或损耗。

## 7. 持续运输

```ts
interface ContinuousTransportPlan {
  id: number;
  fromBlockId: number;
  toBlockId: number;
  commodityId: number;
  amountPerPeriod: number;
  period: number;
  priority: number;
  active: boolean;
}
```

持续运输每期尝试执行玩家设定的数量：

- 来源库存不足时，按实际可用量运输；
- 路线容量不足时，按容量运输；
- 目标区块库存已满时，按配置暂停、转入目标缓冲或损耗；
- 路线中断时，计划保留但本期不完成；
- 玩家可以取消、修改或替换计划。

持续运输不读取价格，也不主动改换目标。

## 8. 贸易与价格

### 8.1 商品价格状态

商品可以处于以下状态：

```text
无价格
→ 有交换记录但无统一价格
→ 区块价格
→ 区块间可比较价格
```

只有贸易机制解锁并满足商品、货币和市场条件后，商品才进入价格结算。

### 8.2 贸易订单

贸易系统根据区块的剩余、缺口、库存、货币和运输条件自动生成：

- 卖单；
- 买单；
- 运输订单。

贸易运输必须满足：

- 来源区块存在可出售库存；
- 目标区块存在有效需求；
- 买方具有支付能力；
- 图路径存在可用运输能力；
- 成交后的收益能够覆盖运输成本与风险。

### 8.3 到岸价格

贸易使用目标区块的到岸成本比较：

```text
到岸成本
= 来源价格
+ 运输成本
+ 损耗成本
+ 关税
+ 风险成本
```

具体价格公式、价格上下限、买卖优先级和货币规则属于后续市场细案，不在本版固化。

## 9. 商品与工具演进

商品不是开局全部存在，而由配置条件逐步启用。

```text
粗石器
→ 磨制石器
→ 铜制工具
→ 青铜工具
→ 铁制工具
→ 钢制工具
→ 机械工具
→ 自动化设备
```

不同工具可以改变：

- 可用生产方法；
- 生产效率；
- 耐久与维护需求；
- 原料需求；
- 可生产商品范围。

商品的解锁条件由技术、知识、原料、设施和劳动力共同决定，不由程序分支硬编码。

## 10. 玩家操作边界

玩家操作集中在系统层级，不进入人口和库存微操：

| 操作 | 出现阶段 |
| --- | --- |
| 调整生产活动 | 生产出现后 |
| 建造储存设施 | 储存技术出现后 |
| 发起一次性调配 | 手动调配出现后 |
| 建立持续运输 | 市场出现后 |
| 调整贸易规则 | 贸易出现后 |
| 设定贸易优先级 | 贸易出现后 |

玩家不直接决定：

- 单个居民吃什么；
- 每件商品进入哪个仓位；
- 运输队逐日移动；
- 市场逐笔寻找交易对象。

## 11. 系统边界

本文不设计：

- 资源与建筑的具体产出公式；
- 人口增长与职业分配公式；
- 货币如何发明；
- 信用、银行和金融市场；
- 税收具体公式；
- 战争战斗结算；
- 军事装备生产方法；
- 商品完整目录与全部解锁条件。

这些内容由对应系统负责，市场系统只接收产出、需求和运输条件，并返回库存、缺口、价格和贸易结果。
