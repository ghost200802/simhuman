# 政治线通则

**定位：** 政治线这一类系统的通则。**只写要求与禁止。**
**边界：** 不含任何一条具体政治线的内容，不含数值，不含依据。

---

## 一、政治线是什么

**政治线是一条制度成长线。它有自己的经验值，按顺序解锁条目。**

与科技节点并列，但计量完全不同：

| | 科技节点 | 政治线经验 |
| --- | --- | --- |
| 本质 | **技能**——会失传 | **制度**——学会了就不会忘 |
| 值域 | 0–100，可跌 | 累积值，**不清零** |
| 失败后果 | 跌破 50 失效，需重新爬满 100 | 无失效，最多涨得慢 |
| 推进方式 | 主动投入劳动 | **被动累积**——被麻烦推着涨 |
| 解锁物 | 能力（能做什么） | 政策（**允许怎么管**） |
| 状态 | 只有 0 / 1 | 已解锁的条目是**始终可用的菜单** |

> **科技线回答"你会做什么"，政治线回答"你能怎么管"。**

---

## 二、运转规则

1. **经验独立。** 每条政治线各有一个经验值，**互不通用**。
2. **选用独立。** 玩家可以**随意组合**使用不同的政治线，互不排斥、互不锁定。
3. **条目的解锁条件**由两部分构成：

```
解锁条件 = 本线经验达到阈值  +  附加依赖（可为空）
```

**附加依赖的允许类型：** 某项**全局 flag**、某个**科技节点**已解锁、另一条政治线的某个条目、某项状态条件。**不得**把时代作为解锁条件。

4. **解锁是扩菜单，不是替换。** 已解锁的条目**一直可用**。**不得禁止玩家用低级的条目。**
5. **条目分两类：**

   | 形态 | 特征 |
   | --- | --- |
   | **方式** | 互斥选项，可切换，**切换有一次性代价** |
   | **开关** | 解锁后才可调参数；不解锁则该项行为被锁在一个默认值上 |

   **开关型条目把"默认值"变成一种压力**——默认值不是被规则禁止，是玩家还没有办法。这个区别很重要。
6. **不绑定时代。** 政治线的推进**不由时代转换触发，也不由时代门槛限制**。它在任何时代都按自己的经验与依赖推进。反过来，任何时代都不要求某条政治线走到哪一步。

---

## 三、与其他系统的接口

| 上游 | 作用 |
| --- | --- |
| **时间** | 政治线经验的底速来源 |
| **叛乱与独立事件** | 政治线经验的**主要加速来源** |
| **负面事件**（灾害、饥荒、继承纠纷、代理人叛乱） | 同上 |
| **区块** | 政治线条目的作用对象。多数条目**按区块生效** |
| **村落凝聚力 / 叛乱值** | 条目效果的**主要读出位置** |
| **人口 / 教育值** | 部分政治线的**输入条件** |

| 下游 | 作用 |
| --- | --- |
| **统治方式** | 政治线的直接产物 |
| **上缴与再分配** | 统治方式的经济后果 |
| **科技节点** | 部分条目解锁或加速科技 |

## 四、写作规范

**每条政治线两份文档，分开存放：**

| 文档 | 只写 |
| --- | --- |
| **游戏设定** | 玩家看到什么、能做什么、会发生什么 |
| **依据与推导** | 文献依据与推导过程 |

### 游戏设定的硬性要求

1. **每一项都必须写成三件套**：**玩家看到什么读数 / 玩家做什么操作 / 会发生什么结果**。
2. **落不到操作面的条目不予收录。** 只有概念、说不出玩家点哪里，就不写进去。
3. 新增任何读数前，先回答：**删掉它，核心体验会损失什么。** 答不出来就不加。
4. **不引入玩家无法验证的读数。** 玩家看不见、也无法从结果感知的，等于不存在。
5. 每个读数必须标明**位置**（全局一条，还是每区块一条）与**值域**。

### 依据与推导的尾部三节

**必须有，顺序不得调整：**

```
查不到、有争议、未定的部分
设计取值标注
来源
```

- 「查不到、有争议、未定」**如实记录否定的结果**，查不到就说查不到，不编造。
- 「设计取值标注」逐条列出哪些是**设计决定、不是文献结论**，与文献数字显式分开。
